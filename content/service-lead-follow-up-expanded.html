An inquiry should become something you can act on: a saved record, a prepared reply, and a next action you can find tomorrow. This walkthrough connects a Tally form to Google Sheets, then uses a two-step Zapier workflow to create a Gmail draft. You review the facts and send it yourself.

The practical answer

Let the form save the record. Let a small automation prepare the reply.

Use Tally’s native Google Sheets integration for the first handoff. Then connect Google Sheets: New Spreadsheet Row → Gmail: Create Draft in Zapier. That gives Zapier one trigger and one action. The draft stays in Gmail until you inspect it and choose Send.

AUTOMATIC

Completed Tally submission → raw Google Sheets row → Gmail draft

YOUR REVIEW

Check request and recipient → send one useful reply → record the next action → close or continue

The sheet is a lightweight register. It does not become a full CRM with automatic deal history, ownership routing, reply detection, or follow-up suppression. Use this route when one person can review the queue reliably. If you already operate HubSpot, keep the contact and dated task there rather than creating a second source of truth.

The documented building blocks are Tally’s native Sheets integration and Zapier’s Sheets-to-Gmail-draft recipe. The field contract and operating process below are our implementation design.

01 / Decide what a good reply needs

Start with six fields and one accountable owner.

The fictional business in this example is North Park Painting. It accepts inquiries about interior and exterior painting in North Park and Eastfield. It has not inspected the property, confirmed availability, or priced the work. The first reply collects useful details. It does not quote a price or reserve a date.

02 / Capture a complete request

Build and publish the Tally form.

Create a form titled Painting inquiry. Type a slash or use the plus control to add the question types from the table. Open each question’s settings with its left-side block handle and mark the required questions. Add the introduction and thank-you message below, review the preview, then publish.

In the published form’s Settings → Email notifications, turn on Self email notifications. The standard free notification gives the form owner another place to notice an incoming inquiry. It does not mean the customer has received a reply. Official notification instructions.

Checkpoint: open the public form in a signed-out browser. Confirm the required fields are visible, the privacy link works, and the thank-you message makes no promise you cannot meet. Keep the form link handy; later tests must use this published version.

03 / Save the request before drafting

Connect Tally directly to Google Sheets.

  1. Open the published form’s Integrations tab and choose Connect beside Google Sheets.
  2. Sign in to the intended Google account and grant the requested connection access.
  3. Name the connection Painting inquiry register. Create or select the spreadsheet and destination sheet.
  4. For a new workflow, leave Export existing submissions off unless you have deliberately planned a historical import. Complete the connection and save.

Before creating the Zap, give the workbook and intake tab simple names such as Service Inquiries and Intake. Submit the fictional example using a controlled real email address. Verify that one complete row appears. Keep Tally’s generated metadata columns and the actual header names; match the six answers to the field contract above.

Tally generates a distinct Submission ID for each submission. Its Respondent ID identifies a respondent across submissions and is a different concept. Locate the exported submission identifier and use it as the inquiry reference. If your export does not expose it as expected, inspect the integration output before proceeding; email address alone is not a unique inquiry key. Tally’s identifier definitions.

Keep the intake tab stable.

This is a real compatibility trap: Tally says its integration can tolerate moving or deleting columns, while Zapier warns that structural changes can break a connected sheet workflow. Follow the stricter rule for the combined system. Keep Intake as an append-only record. Do not sort it, insert gaps, rename headers, delete old rows, or add formulas down unused rows while the Zap is active.

Keep your working status list in a separate Review tab that the Zap does not watch. For this small workflow, the reviewer adds or updates that record manually using the Submission ID. That extra human action makes ownership and follow-up visible without adding another paid automation action or altering the intake stream.

04 / Prepare the reply

Create a two-step Zap with explicit field mapping.

  1. Create the trigger. In a new Zap, choose Google Sheets and New Spreadsheet Row. Connect the Google account with access to the intake sheet. Select Service Inquiries and Intake. Do not choose a trigger that also runs when existing rows are updated.
  2. Load a real test record. Test the trigger after submitting your controlled form entry. Select the sample containing your test name, service, email, and submission identifier. If those fields are missing or shifted, fix the sheet/connection before adding the next step.
  3. Create the action. Choose Gmail and Create Draft. Connect the inbox from which the business will reply. Confirm the account address. Create Draft Reply is a different action for an existing email thread; this new form request needs a new draft.
  4. Map the fields below. Insert Zapier’s field tokens from the trigger rather than typing the example values. Leave CC, BCC, and attachments empty for this first version. Choose the plain-text body option if the action exposes a body-type setting.
  5. Test once and inspect Gmail. Testing an action can create a real draft. Open Gmail’s Drafts folder and verify the complete message. Keep the Zap unpublished until the acceptance cases are understood.

05 / Finish the response

Review the customer’s actual request before sending.

Open the intake record and Gmail draft together. Check the recipient character by character, confirm the requested service and area, and remove questions already answered. Search Gmail and the review register for the submission reference and the address. A repeat request might be a correction or a second project; it is not automatically a duplicate to discard.

Send only when the reply fits the request. Record the actual sent time and set a next action in the Review tab. For the example, a response sent Monday, November 2, could be reviewed on Wednesday, November 4, in the business’s stated time zone. Adjust for your working days and commitments.

This workflow does not detect replies or send that follow-up automatically. The owner checks the inbox first. A date in a sheet is a reminder for your process, not a scheduled email. Do not add an automatic chasing sequence until you can reliably stop it on a reply, refusal, or closed request.

Optional: use AI to improve a difficult reply.

For a request that needs more thought, provide an AI assistant with a de-identified summary and the approved business facts. Ask for a draft, then compare every claim with the original record. This optional writing step is separate from the two-step Zap and does not require an AI API subscription.

Copy: a constrained drafting prompt

Draft a short reply using only these approved business facts and
this de-identified inquiry summary.

Approved facts: [services, area, pricing rule, scheduling rule]
Inquiry summary: [omit name, email, full address, and private details]
Already answered: [facts the customer supplied]
Missing information that affects the next step: [specific items]

Acknowledge the request, ask only unanswered necessary questions,
and explain what happens next. Do not invent a quote, availability,
inspection result, guarantee, credential, or completed action.
If a fact is missing, mark it NEEDS REVIEW. Return a draft only.
06 / Test what can actually go wrong

Check the record, draft, and stopping behavior separately.

Use controlled addresses throughout. A Zap action test can create a draft even when the workflow is unpublished, so inspect and label test drafts. When the configuration is correct, publish the Zap and submit a fresh form entry to check the live trigger. Record results against the submission reference.

The duplicate boundary: this two-step recipe has no separate lookup or durable deduplication action. It prepares drafts for review. If you need automatic sending with strict duplicate prevention, you need a stronger design and additional tests. Tally’s sync log and Resend control: integration troubleshooting. Sheet hazards and the pause → change → retest → publish procedure: Zapier spreadsheet rules. Trigger repair details: Zapier’s trigger troubleshooting.

Make changes in a controlled order.

Pause the connected Zap before changing the intake structure. Record the last handled submission ID, make the intended change, reload the trigger sample, and inspect every mapping. Create one controlled new submission, verify its destination, then republish. Reconcile anything received while paused; do not assume all historical events will automatically replay.

At each queue review, compare recent Tally submissions with the register and drafts. A useful daily note is: received / recorded / draft present / reviewed / reply sent / next action assigned. Those are separate states. Counting rows alone cannot tell you whether customers received a useful answer.

Watch monthly task use. With one successful Gmail action per inquiry, 60 inquiries would consume 60 tasks for this Zap. Other automations and replays share the same account allowance. That is capacity arithmetic, not a traffic forecast. If volume outgrows the free allowance, choose a paid plan deliberately or continue reviewing the saved register manually while deciding.

When to move to a CRM: you need multiple owners, deal stages, reliable history across channels, or reminders that should not depend on checking a sheet. HubSpot’s contact records and associated tasks are one documented path. The same operating rule applies: every active inquiry needs an owner, an accurate state, and a dated next action.
